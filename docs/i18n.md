# Traductions

Le jeu parle 9 langues : français (source), anglais, espagnol, allemand, néerlandais, italien, portugais, japonais et chinois simplifié. Résumé côté joueur : [Paramètres et langues](../README.md#paramètres-et-langues).

## Fichiers

| Fichier | Rôle |
| --- | --- |
| [i18n/fr.ts](../src/i18n/fr.ts) | **Référence** : l'objet `fr` définit toutes les clés. Le type `Key = keyof typeof fr` en découle. |
| [i18n/en.ts](../src/i18n/en.ts), `es`, `de`, `nl`, `it`, `pt`, `ja`, `zh` | Typés `Record<keyof typeof fr, string>` : TypeScript refuse une clé manquante ou en trop. |
| [i18n/index.ts](../src/i18n/index.ts) | `Lang`, `LANGS`, `DICTS`, `detectLang`, `setLang`, `lang`, `t`, `tn`, `listJoin`, `formatDate`, `ordinal`, `themeName`, `themeBlurb`, `applyDom`, `locale`, `has`. |

Les clés sont rangées par écran avec des commentaires `// ---------- … ----------` (barres, accueil, tutoriel, aide, toasts, victoire, défi du jour, série, zone/pub, paramètres, styles, défis des styles, formes, ligue, erreurs en ligne).

## Fonctionnement

- **Langue au démarrage** ([main.ts](../src/main.ts)) : `setLang(detectLang(save.settings.lang))` avant de construire quoi que ce soit, puis `applyDom()`. `detectLang` : choix enregistré s'il est valide, sinon les deux premières lettres de `navigator.language` si le jeu les parle, sinon `'en'`. Sans appel à `setLang` (tests), la langue est le français.
- **Dans le code** : `t('level.title', { n: 4 })` remplace les `{n}` ; une clé absente de la langue courante retombe sur le français, puis sur la clé elle-même.
- **Pluriels** : `tn('count.hint', n, vars)` choisit `count.hint_one` ou `count.hint_other` avec `Intl.PluralRules` de la langue (français : singulier pour 0 et 1 ; anglais : pour 1 seulement ; japonais et chinois : toujours `_other`). `{n}` est rempli automatiquement. `PluralKey` est déduit des clés en `_one`.
- **Listes et dates** : `listJoin(['1 zone', '3 indices'])` → « 1 zone et 3 indices » (`Intl.ListFormat`) ; `formatDate`. `locale()` prend la variante de l'appareil quand elle correspond à la langue (en-GB, fr-CA…).
- **Rangs** : `ordinal(n)` est codé à la main par langue (« 1er », « 2e », « 1st », « 1.º », « 1. », « 1位 », « 第1名 »…).
- **Dans le HTML** ([index.html](../index.html)) : `applyDom()` remplit
  - `data-i18n="clé"` → `textContent` ;
  - `data-i18n-html="clé"` → `innerHTML`, pour nos propres textes contenant `<b>` (et rien d'autre) ;
  - `data-i18n-attr="aria-label:clé;placeholder:clé"` → attributs.
  
  Le texte français reste écrit dans le HTML comme valeur par défaut.
- **Styles et avatars** : `themeName(id)` / `themeBlurb(id)` lisent `theme.<id>.name` / `.blurb` ; les avatars `avatar.<key>`.
- **Moteur sans texte** : [src/core/](../src/core/) ne contient aucun texte affiché ; les formes sont traduites à l'affichage (`shape.<id>`, `shapeName` dans [hud.ts](../src/ui/hud.ts)).
- **Changer de langue** dans les paramètres recharge la page (voir [ui-and-input.md](ui-and-input.md#paramètres)).
- **Erreurs du serveur** : [social.ts](../src/online/social.ts) traduit les codes (`name_banned`…) via la table `MESSAGES` vers des clés `error.*`.

## Ajouter une clé

1. L'ajouter dans [fr.ts](../src/i18n/fr.ts), dans la bonne section. Placeholders en `{nom}`. Pluriel : deux clés `xxx_one` et `xxx_other`.
2. L'ajouter dans les 8 autres fichiers, avec **les mêmes placeholders et les mêmes balises** (`<b>`). `npm run typecheck` signale les fichiers où elle manque.
3. L'utiliser : `t('ma.cle')` / `tn('ma.cle', n)` dans le code, ou `data-i18n="ma.cle"` dans le HTML.
4. `npm test` ([i18n.test.ts](../tests/i18n.test.ts)).

Typographie : quelques textes français contiennent une espace insécable (U+00A0) devant `!` ou `:` ; **les autres langues ne doivent contenir ni U+00A0 ni U+202F** (le test les refuse). Attention aux copier-coller depuis le français.

## Ajouter une langue

1. Créer `src/i18n/xx.ts`, typé comme [en.ts](../src/i18n/en.ts) : `export const xx: Record<keyof typeof fr, string> = { ... }`.
2. Dans [i18n/index.ts](../src/i18n/index.ts) : ajouter `'xx'` au type `Lang`, à `LANGS` et à `DICTS` (avec l'import).
3. Vérifier `ordinal()` : ajouter un cas si la langue n'utilise pas le format anglais (`1st`, `2nd`…).
4. Ajouter le bouton dans le sélecteur des paramètres de [index.html](../index.html) : `<button class="lang-opt" role="radio" aria-checked="false" data-lang="xx" lang="xx">Nom</button>` dans `#set-lang`.
5. `npm test`. Pour une langue sans pluriel ou à pluriels particuliers, `Intl.PluralRules` choisit `one` ou `other` ; les autres catégories (`few`, `many`) retombent sur `_other`.
6. Mettre à jour le README (liste des langues).

## Ce que vérifie [i18n.test.ts](../tests/i18n.test.ts)

- chaque langue a exactement les clés du français ;
- aucun texte vide ;
- mêmes placeholders et mêmes balises que le français, clé par clé ;
- chaque clé `_one` a sa clé `_other` et inversement ;
- chaque style de `THEMES` a `theme.<id>.name` et `.blurb`, chaque avatar `avatar.<key>` ;
- pas d'espace insécable hors du français ;
- exemples de `t`, `tn`, `listJoin`, `ordinal` en français, anglais, japonais et chinois ;
- texte partagé du défi du jour en anglais (`shareText`, `rewardText`) ;
- `detectLang` (choix enregistré, puis langue de l'appareil, puis anglais).
